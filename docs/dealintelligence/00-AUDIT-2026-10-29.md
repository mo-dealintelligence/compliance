# Comp AI Community Edition — self-host audit for dealintelligence.io

Date: 2026-10-29 · Repo: trycompai/comp @ 2f4b9a5 (v1.50.0) · Auditor: Claude (session for Mo)

Purpose: decide whether and how to self-host Comp CE for Deal Intelligence LLC (SOC 2 Type 1 achieved on Humadroid; moving toward Type 2), before touching any implementation. Findings below are from reading the code, running `bun install`, and building the API/portal/app in a clean container.

---

## 1. Verdict in one paragraph

The platform is real and the compliance core (frameworks, controls, policies, evidence tasks, vendors, risks, people, employee portal, auditor view, API + MCP) is solid and fully open. But **the self-hosting path shipped in the repo does not work as documented**: the root `docker-compose.yml` omits the NestJS API that every page and every login depends on; the seeder points at a file that doesn't exist; transactional email (and therefore magic-link/OTP login) is routed through Trigger.dev; ~6 features are hidden behind PostHog feature flags that read `false` with no PostHog; and the public **trust center frontend is not in the repo at all** (deleted July 2025 as a "private package"). That combination is almost certainly what produced the "missing features" and "hidden lead magnet" experience last time. All of it is fixable with a small, well-scoped set of patches in a fork — none of it requires rewriting the product.

## 3. Things that will bite (ranked)

1. **API not in compose / docs** — add an `api` service + `NEXT_PUBLIC_API_URL`, `BASE_URL`, `SERVICE_TOKEN_*`, `INTERNAL_API_TOKEN`.
2. **Session cookies across subdomains**: `getCookieDomain()` only sets a shared cookie domain for `*.trycomp.ai`. For `app.`/`api.`/`portal.dealintelligence.io` we must either patch it to use `COOKIE_DOMAIN` env, or put app+api behind one hostname via reverse proxy. (Patch is ~10 lines.)
3. **Hard-coded trust of `*.trycomp.ai` and `*.trust.inc`** in CORS/CSRF origin checks even when `AUTH_TRUSTED_ORIGINS` is set — remove.
4. **`NEXT_PUBLIC_SELF_HOSTED` is never passed as a Docker build ARG**, so the "book a call / Customer Success Rep" upgrade gate can still appear. Add ARG + set `SELF_HOSTED=true` on the API. Also remove the "verified @trycomp.ai email auto-approves" rule.
5. **PostHog feature flags default false** → hides Trust portal nav, Security Questionnaire (404s), ISMS tab, Timeline, AI policy assistant, browser automations. Patch `getFeatureFlags()` to return a self-hosted map.
6. **API refuses to boot without `MACED_API_KEY`** (pentest vendor module constructor throws). Use a dummy or make the module optional.
7. **Seeder in compose runs `seed.js`; only `seed.ts` exists.** Migrator stage pins Prisma ^6.14 vs repo 7.6.0. Rewrite migrator/seeder stages.
8. **Billing/pentest/background-check upsells** always visible (Billing tab, "Start free trial", "A Comp engineer will scope…", 402 paywalls on pentest + background checks hitting Comp's third-party vendors). Hide when self-hosted.
9. **Telemetry**: Sentry has a hard-coded Comp AI DSN fallback (gated to `VERCEL_ENV=production`), Vercel Analytics always rendered, Cloudflare Zaraz on checkout, PostHog proxies, logo.dev calls using Comp's public token, email logo/footer from assets.trycomp.ai, training-certificate PDF fetches Comp logo. All removable.
10. **Branding**: "Comp AI" strings in ~40 app files, portal header/title/auth page, all 15 email templates, favicons; navbar `Logo` lives in the MIT-licensed `@trycompai/design-system` npm package (source shipped → overridable). Employee portal has no org-logo setting; trust portal has logo/colour/favicon/custom-domain settings.
11. **Design**: two overlapping component libraries mid-migration (680 files on design-system, 437 on legacy shadcn `@trycompai/ui`, 271 still on lucide). Legacy dark-mode tokens are a copy of light. Fonts: General Sans + Geist Mono. Overall it's a competent Linear-ish shell; the "bad design" impression is most likely the unbranded/half-gated state plus mixed component styles. Fixable by (a) branding pass, (b) forcing light theme, (c) hiding the upsell surfaces. Not a redesign.
12. **Integrations usable on self-host**: only the code manifests — AWS (CloudTrail, EC2, IAM, KMS, RDS, S3, env separation), GCP, Azure, GitHub (branch protection, Dependabot, code scanning, 2FA), Google Workspace (employee sync, 2FA), Vercel, Aikido, Rippling. The 590-entry "integrations-catalog" is metadata only (check DSL intentionally excluded). Deeper AWS scanners exist in `apps/api/src/cloud-security`. No Okta, no PropelAuth, no Clay/HubSpot/Slack manifests.
13. **Import path**: bulk policy upload is **PDF only** (25 files × 100 MB) and stores them as PDF-display policies; no markdown/docx importer. Scriptable API (`X-API-Key`) covers policies, tasks + attachments, vendors, risks, people, controls. No bulk evidence importer → script it.

## 5. Proposed plan (for approval)

**Phase 0 — Fork & harden (code, ~1 day)**
- Fork to `dealintelligence/comp` (AGPL obligations: we keep source available for the modified instance — fine for an internal tool; confirm Mo is OK with AGPL).
- Patches, each as its own commit: compose with `api`; fix migrator/seeder; Dockerfile ARGs for `NEXT_PUBLIC_SELF_HOSTED`, `NEXT_PUBLIC_APP_ENV`; `COOKIE_DOMAIN`; strip `*.trycomp.ai`/`*.trust.inc` trust; self-hosted feature-flag map; `MACED` module optional; hide billing/pentest/background-check/automation upsells + referrals + checkout tracking under self-hosted; remove Sentry DSN fallback, Vercel Analytics/BotID, Zaraz, logo.dev token (swap to self-hosted logos), assets.trycomp.ai; branding pass (app, portal, emails, favicons, design-system Logo override); envs.ts URL helpers from env; Trigger project ids from env.
- Build CI on a machine with ≥8 GB RAM.

**Phase 1 — Infra on AWS us-east-1 (matches the system description)**
- Option A (recommended, cheapest to operate solo): one ECS Fargate service per app (api/app/portal, later trust) + RDS Postgres 16 (encrypted, private subnet) + S3 bucket (SSE-KMS) + ALB with ACM certs for `app.`, `api.`, `portal.`, `trust.dealintelligence.io`. Terraform or CloudFormation alongside `di-backend-api-prod` so it becomes part of the audited stack.
- Option B: single EC2 + docker compose + RDS. Faster, weaker story for Type 2.
- Trigger.dev Cloud (free tier is enough) with two projects; Resend on `mail.dealintelligence.io`; Upstash Redis free tier (or `MOCK_REDIS` + patch); Google OAuth on the dealintelligence.io Workspace tenant.

**Phase 2 — Content migration (scripted, idempotent, scripts kept in `scripts/di-migration/` in the fork)**
- Create org, enable SOC 2 (v1) framework; map Humadroid control matrix → Comp SOC 2 requirements (CC/A/C/PI/P ids are the same TSC ids).
- Policies: convert the 7 policy PDFs to text → TipTap JSON (editable, versioned, acknowledgable) rather than PDF-display; fix placeholders/versions during conversion; replace "Humadroid" references with Comp.
- Evidence: upload 45 screenshots + 3 logs as task attachments on the matching tasks; attach procedures/plans/records to their controls.
- Vendors (AWS, PropelAuth, GitHub, Google Workspace, Resend…), risks (from the Humadroid register screenshot → re-enter), people (Mo, William Wickey contractor), training records.
- Connect AWS + GitHub + Google Workspace integrations for continuous evidence (this is what Type 2 wants).

**Phase 3 — Trust center**
- Build `apps/trust` (small Next.js app, ~2 days) against the existing public API: overview, framework badges, policy list with NDA-gated access requests, FAQs, custom links, custom domain `trust.dealintelligence.io` (already referenced in the v2.0 privacy policy).

**Phase 4 — Verify**
- Fresh-browser walkthrough of login, policy acknowledgment in portal, evidence upload, auditor view export; screenshot pack; separate review agent checks every control in the matrix has at least one piece of evidence in Comp.
