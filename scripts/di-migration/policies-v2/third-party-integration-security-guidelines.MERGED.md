# Third-Party Integration Security Guidelines — MERGED (no v2)

Per rulebook R7, the Third-Party Integration Security Guidelines v1.0 (November 13, 2025) is retired as a standalone document. Its content now lives in two v2 documents:

| v1 section | Destination |
|---|---|
| §1 Purpose, §3 Policy Statement, §2 Scope (integration bullets) | API Security and Rate Limiting Standard v2.0 §8 (Integration security) intro and §2 Scope |
| §4 Roles and Responsibilities (CEO / Technical Integration Lead / Security Operations) | API Security Standard v2.0 §8 intro — consolidated to the CEO (R2) |
| §5.1 Pre-Integration Assessment table | Vendor Management Policy v2.0 §5.3 (Pre-Integration Assessment) |
| §5.2 Authentication and Authorization (5.2.1 standards, 5.2.2 credential management) | API Security Standard v2.0 §8.1 and §8.2 |
| §5.3 Data Exchange Security (encryption, data minimization) | API Security Standard v2.0 §8.3 |
| §5.4 Integration Architecture Patterns (approved patterns table, prohibited practices) | API Security Standard v2.0 §8.4 |
| §6 Customer-Controlled Integrations (CRM, Slack) | API Security Standard v2.0 §8.5; the "not a sub-processor" statement stays in Vendor Management Policy v2.0 §8.3 |
| §7 Monitoring and Logging | API Security Standard v2.0 §8.6 |
| §8 Security Testing and Vulnerability Management | API Security Standard v2.0 §8.7 |
| §9 Incident Response (integration incidents, third-party breach response) | API Security Standard v2.0 §11.1–11.2; vendor breach steps (credential rotation, vendor re-assessment) in Vendor Management Policy v2.0 §9.2 |
| §10 Compliance Requirements (GDPR/CCPA/OWASP ASVS, data subject rights) | API Security Standard v2.0 §8.9; DPA requirements in Vendor Management Policy v2.0 §5.3 and §6.1 |
| §11 Integration Lifecycle Management | API Security Standard v2.0 §8.8 |
| §12 Related Documents, §13 Review and Updates | Superseded by the related-documents and review sections of the two destination documents |

All cross-references to "Third-Party Integration Security Guidelines" in other v2 documents should point to the API Security and Rate Limiting Standard (section 8, Integration security) for technical controls, or to the Vendor Management Policy for assessment, DPA and sub-processor requirements.
